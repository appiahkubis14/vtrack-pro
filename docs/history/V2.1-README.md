# V-Track Pro v2.1 — Commercial Productization & Specialized Tracker Modules

Extends the v1/v2 platform with 8 new modules: Product Catalog & Pricing,
Quote Engine & Leads, Portable/Covert Asset Tracking, International
Roaming & Border Crossing, Voice Monitoring & Audio Evidence, Enhanced
Theft Recovery, Public Website API, and Tenant Commercial Management.

## What's real here

Every module below was built against a live Postgres+Redis stack and
tested with actual requests — not just written and assumed correct. A
handful of genuine bugs were caught and fixed in the process (documented
inline in the relevant source files' comments, and summarized below).

## New database migrations

`backend/src/database/migrations/1700000000017` through `...024` — run
with `npm run migration:run` same as before. Covers: product catalog,
quotes/leads, portable assets, roaming/border-crossing, audio monitoring,
theft recovery, public content, and tenant commercial columns on
`organizations`.

**One manual step**: `country_boundaries` ships empty. Real border-crossing
detection needs actual country polygon data — see the migration file's
docblock for the exact `ogr2ogr` import command against Natural Earth's
admin-0 boundaries (public domain). Tested in this build with simplified
hand-inserted test polygons for Ghana/Togo, which is not a substitute for
real boundary data in production.

## New backend modules

`backend/src/modules/{catalog,commercial,portable,roaming,audio,theft-recovery,public,realtime}/`

Each has its own service/controller/entity layer, wired into `app.module.ts`.
The `realtime` module is a shared WebSocket gateway (namespace `v2-events`)
that every other new module broadcasts through — join an org room with
`socket.emit('joinOrg', organizationId)` before listening.

## New frontend pages

`frontend/app/{quotes,leads,catalog,portable-assets,roaming,audio,theft-recovery,settings}.html`

All wired to the real endpoints above, using the same horizontal-nav shell
and `vtrack-api.js` client built for the base platform. The nav now groups
these under "Commercial" and "Specialized" dropdowns.

## Genuine bugs found and fixed while building this

Building real integration surfaces real bugs — these wouldn't have been
caught by writing code that merely compiles:

1. **Lead/quote status sync** — the lead status-transition table was too
   strict for how quotes actually get sent in practice (a lead often jumps
   straight from `new` to `quote_sent`), causing a downstream failure to
   mask an already-successful quote action.
2. **Covert-mode self-approval bypass** — the portable-asset covert
   approval check compared against the wrong field (`responsibleUserId`
   instead of who actually requested it), so self-approval wasn't really
   blocked. Fixed and verified with two real, distinct user accounts.
3. **Circular evidence-integrity check** — the audio evidence export
   almost hashed the stored hash against itself (trivially "passing" every
   time). Rebuilt around real local file storage so tamper detection
   actually works — verified by corrupting a real file on disk and
   confirming the export correctly refuses.
4. **Immobilization false-failure** — a real, successful immobilization
   command could report back as "failed" to the caller if a secondary
   case-status update hiccuped afterward — dangerous in an actual theft
   scenario. Fixed to never let secondary bookkeeping mask a
   safety-critical action that already succeeded.
5. **Cross-tenant data leaks** — several v1/v2 endpoints (alerts, devices,
   dashboard, digital twin) trusted a client-supplied `organizationId`
   query param instead of deriving it from the JWT.
6. **`quoteStatusChanged` never firing** — the quotes controller never
   passed the caller's `organizationId` through, so it was never persisted
   on the quote row and the WebSocket event had nowhere to broadcast.

## Known gaps, stated plainly

- **No payment gateway integration** — `invoices`/`orders` track billing
  state but don't process real payments (Paystack/Flutterwave/Stripe would
  need adding).
- **SIM-swap detection is a webhook, not a device signal** — standard
  GT06/TK103 packets don't carry ICCID, so this needs a real IoT SIM
  provider's callback, not GPS telemetry.
- **Multi-language notification templates** — the infrastructure exists
  (`tenant_notification_templates`) but the actual Twi/Ewe/Hausa/French/
  Portuguese translations need a translation vendor, not an engineer.
- **Audio storage is local disk** — `AudioStorageService` is built so
  swapping in S3/GCS is a small change, but it isn't done here.
